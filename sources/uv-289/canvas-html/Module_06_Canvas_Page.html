⚠️ Critical: AI-Assisted Development Ground Rules

This module introduces Claude Code as a development tool. These rules are non-negotiable:

  • You must evaluate every line of AI-generated code. If you cannot explain what a line does, you cannot ship it.
  • No "slot machine" prompting. Do not keep re-running the same prompt hoping for better output. If Claude Code gives you bad output, refine your prompt with more context.
  • CLAUDE.md is required. This file configures Claude Code for your project. It documents your project context, coding standards, and constraints.
  • Log your prompts. Maintain a prompt log documenting what you asked, what you got, and what you changed. This is evidence of your engineering judgment.
  • Iterative prompting over one-shot prompting. Break complex tasks into small, testable steps. Verify each step before moving on.

The goal is not to generate code faster. The goal is to develop better software with an AI collaborator while maintaining full code ownership.

🔬 Hands-On Activity: Claude Code Onboarding — Sacred Flow with AI (90-120 min)

What you'll experience:

This is the most important lab in the course. You will learn the development workflow that carries you through the rest of the capstone. Using a Flask login toy project, you'll practice every step of the Sacred Flow with Claude Code as your AI collaborator.

The Sacred Flow:

  1. Issue: Write a clear issue describing the feature or bug
  2. Branch: Create a feature branch from main
  3. Develop: Use Claude Code with iterative prompting — verify each step
  4. PR: Create a pull request with a meaningful description
  5. Review: Review every line — annotate changes
  6. Merge: Merge only after review passes

Anti-Patterns to Avoid:

  • Slot Machine: Re-running the same prompt hoping for different output
  • Blind Accept: Accepting AI code without reading every line
  • Context Dump: Pasting your entire codebase instead of focused context
  • One-Shot Hero: Trying to generate an entire feature in a single prompt

💡 Andrew's Tips for Success

  • CLAUDE.md is your most important file this module: A well-configured CLAUDE.md means Claude Code understands your project context. A bad one means garbage output. Invest the time.
  • Small PRs beat big PRs every time: One feature per PR. If your PR touches 15 files, it's too big. Break it down.
  • Velocity is a planning tool, not a performance metric: If Sprint 5 velocity is 20 points, plan Sprint 6 for 20 points. Don't plan for 40 hoping you'll "try harder."
  • The prompt log is evidence of engineering judgment: It shows you can direct an AI tool, not just accept its output. This is the skill employers want to see.
  • Code review is a gift: When a classmate finds a bug in your code, they saved you hours of debugging later. Thank them.
  • Commit early, commit often: Small, frequent commits with clear messages. If you lose work because you didn't commit, that's on you.
  • If Claude Code gives you bad output, the problem is your prompt: Add more context, be more specific, break the task into smaller pieces. Iterative prompting always wins.
